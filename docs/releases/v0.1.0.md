# Rish v0.1.0 — Source Preview (unreleased)

**Rish，你的随身 Agent。**

**手机本地执行，模型自由接入。**

This document describes the planned source preview. It is not a published
release or an assertion that a tag already exists. The repository remains
private during preparation. Any eventual GitHub release must be marked
**Pre-release**, even if its tag is the ordinary `v0.1.0` name.

## Included scope

- Native React Native iOS UI, local conversations, preferences, attachments,
  iPad layouts, and bounded app-owned Files operations.
- App-owned Git Projects with pinned libgit2; HTTPS operations and native SSH
  clone/fetch with strict `known_hosts` verification.
- API-driven iOS Agent file/Git tools with native journals, explicit approvals,
  cancellation, and recovery boundaries.
- Clickable plain URLs and Markdown links in conversations. Per-round provider
  text is displayed before the associated tools; reasoning follows the user's
  display preference. New display records survive ordinary transcript cleanup
  and app restart. Previously deleted intermediate text cannot be recovered.
- DSH model catalog configuration and scoped custom API providers. Model
  requests, including selected context, go to the configured provider; local
  tool execution does not imply offline inference.
- Android native API chat, credential storage, session persistence, and
  scoped task-notification support. Android is not at iOS Agent/runtime parity.

## Experimental and unverified paths

The product continues to report `local_substrate`; the complete
`local_harness` gate is not closed. General desktop software compatibility,
arbitrary shell execution, and continuous background execution are not claimed.

The DEBUG iOS guest CGI experiment has separate evidence of an App Agent
starting a local service and Simulator Safari reading, incrementing, and
refreshing its state. It uses a bounded native listener and supervised guest
CGI, not a general Node/Python server. iOS may reclaim background execution
within tens of seconds. The later redesigned promotional screenshot used a
Mac-hosted visual preview and is **not** evidence of native guest execution.

Android Files/Git/Agent execution, JNI runtime integration, and physical Android
acceptance remain outside the verified surface. HarmonyOS Android compatibility
containers do not establish native HarmonyOS support. SSH push, LFS, submodules,
merge/rebase, and complete SSH profile UI acceptance remain separate work.

Official Codex/Claude CLI subscription experiments use optional, separately
prepared inputs. The base source preview does not bundle these executables or
claim that both official subscription flows work. See
[the auth status](../ios-harness-auth-status.md).

## Validation and release gate

The current sprint and remaining gates are tracked in
[open-source-sprint.md](../open-source-sprint.md). Counts below are observations
of a working tree, not CI results for a tagged commit.

- September 10 working-tree checks after the sprint fixes: TypeScript passed;
  Jest **86 suites / 1,702 tests** passed; lint reported no errors and 27
  existing warnings. Run final checks again if executable source changes.
- The signed Simulator build used for the conversation-display acceptance
  passed native presentation owner/hash/cleanup tests (2 cases), separately
  from the CGI/adapter regression set (23 cases).
- Actual Simulator acceptance showed a provider progress sentence, `list_dir`,
  and a final answer in order. The progress sentence remained after restart.
- A subsequent model-identifier rejection exposed a settled-recovery running
  lock leak. The lock fix passed controller regressions and Simulator
  new-conversation acceptance without replaying the old attempt. A signed
  native build and three provider diagnostic/model-strictness tests passed.
  Fresh live-provider CGI startup remains a separate acceptance item.
- The candidate secret scan after the README/screenshot update covered **622
  files**, with no size skips.
  The reachable-history scan covered **162 commits / 1,362 blobs**, with no
  size skips. These finite-pattern scans do not prove absence of every kind of
  secret. Rerun against the final candidate if it changes.
- Portable-source preflight tests passed **9/9** and offline preparation tests
  passed **2/2** (including absent-toolchain rejection before any proxy or
  download). All 165 Xcode project
  identifiers are unique. Fresh native dependency downloads and a complete
  clean-environment build are not established by that preflight.
